# Подлинность сборки и защита от «кряков»

## Главное

- Программа **бесплатная**: ключей активации, пробного периода и подписки нет.
  Все функции доступны сразу после установки.
- Лицензия (`LICENSE`) запрещает продавать программу, выдавать изменённые
  сборки за официальные и добавлять вредоносный код. Технически это
  поддерживается **значком подлинности**, а не блокировкой функций.
- Значок ничего не блокирует и не мешает вам править код под себя. Он нужен,
  чтобы пользователь видел: «это официальная сборка» или «файлы изменены —
  возможно, это чужой «кряк» с вирусом».

## Как устроено

1. Владелец проекта подписывает список хэшей файлов закрытым ключом Ed25519:
   `npm run sign -- sign --key ./integrity-keys/private.pem`
   → создаётся `integrity.json`.
2. Открытый ключ лежит рядом: `integrity-pub.pem`.
3. При запуске (и в «Настройки → О программе») приложение сверяет файлы:
   - `official` — подпись верна, файлы совпадают;
   - `modified` — подпись верна, но файлы изменены (например, кто-то вписал
     в `app.js` свой скрипт и распространяет такую сборку);
   - `tampered` — подпись манифеста не сходится (манифест подделали);
   - `unsigned` — подписи нет; это нормально для сборки из исходников.
4. `public/style.css` **намеренно не входит** в манифест: оформление можно
   менять без предупреждений.

Ограничение честное: если у человека есть права на его компьютер, он может
переписать и сам код, и проверку. Задача значка — сделать «кряки» заметными
для обычного пользователя, а не поймать любого злоумышленника.

## Ключи подписи

```bash
# один раз: создать пару ключей (закрытый — только у владельца проекта)
node tools/integrity-cli.js keygen --out ./integrity-keys --install

# после любых правок в файлах из манифеста
npm run sign -- sign --key ./integrity-keys/private.pem

# посмотреть состояние
npm run sign -- status
```

- `integrity-keys/private.pem` — **не публиковать и не коммитить**
  (папка в `.gitignore`). Потеряете — придётся выпустить новую пару; старые
  сборки станут «неофициальными», пока не подпишете их новым ключом.
- `integrity-pub.pem` — открытый ключ, его можно распространять: он и
  используется для проверки.

## Защита пользователя от вирусов в коде

Помимо подписи сборки, сервер проверяет текст, который пишется в файлы и
запускается в терминале, на типичные вирусные приёмы:

- скачивание кода из интернета и немедленный запуск (`iwr … | iex`,
  `curl … | bash`);
- скрытый PowerShell с закодированной командой;
- `eval` от base64;
- необратимое удаление и форматирование диска;
- автозапуск (реестр `Run`, `schtasks`, `crontab`, папка «Автозагрузка»);
- майнеры, кража паролей и кошельков, reverse shell.

При обнаружении в чате появляется предупреждение с номером строки, а в
терминале — красная строка перед выполнением. Работа не блокируется: вы
всегда можете запустить свой код осознанно.

## Что ещё защищает компьютер

- сервер слушает только `127.0.0.1` и требует одноразовый токен;
- проверяются `Host`, `Origin`, `Sec-Fetch-Site`, стоит CSP;
- агент не выходит за папку проекта и не читает секреты (`.env`, ключи,
  `.git/config`);
- опасные действия агента и команды требуют подтверждения;
- `fetch_url` не ходит на локальные и служебные адреса (SSRF);
- лимиты на размер запросов, вывод терминала и частоту обращений к API.

Подробности — в `SECURITY.md`. О найденных проблемах сообщайте по правилам
из этого файла.
