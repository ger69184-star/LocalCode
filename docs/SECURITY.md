# LocalCode — безопасность

LocalCode — локальный редактор кода с ИИ. Сервер работает **только на этом компьютере** и не должен
быть доступен из сети. Ниже описано, что именно защищено, как это устроено и какие ограничения остаются.

## Что уже сделано

### Доступ к программе
- Сервер слушает только `127.0.0.1` (loopback), а не `0.0.0.0`. Порт меняется, если занят.
- У каждого запуска свой случайный **128-битный токен**. Без него API отвечает `401`.
- Токен передаётся в заголовке `x-token`; в ссылке для браузера — во фрагменте `#token=…`,
  поэтому он не попадает в журналы сервера, прокси и в заголовок `Referer`.
  При запуске с окном (`--app`) токен **не пишется** в `localcode.log`.
- Сравнение токена — `crypto.timingSafeEqual` (без утечки по времени).
- Проверка заголовка `Host`: чужой домен не может «стать» localhost (защита от DNS-rebinding).
- Проверка `Origin` и `Sec-Fetch-Site` для всех `/api/*`: запросы с других сайтов отклоняются
  (защита от CSRF, даже если токен каким-то образом оказался в чужой вкладке).
- Проверяются HTTP-метод и `Content-Type: application/json`; GET ничего не меняет.
- Тайм-ауты сервера против «медленных» клиентов (slowloris).

### Файлы
- Все пути проверяются: `..` и подмена путей запрещены; проверка идёт по **реальному** пути
  (`realpath`), поэтому ссылка вида `проект/link → /etc` не обходит правила. В ограниченном режиме
  разрешены только проект и домашняя папка; в полном доступе — любая папка, но системные каталоги
  по-прежнему закрыты.
- Секретные каталоги закрыты всегда (и в полном доступе): `Windows`, `Program Files`, `ProgramData`,
  `.ssh`, `.gnupg`, `.aws`, `.azure`, `.kube`, `.docker`, `.config`, `.localcode`, `AppData`,
  `Library/Keychains`, `.password-store` и т. п.
- Файлы с секретами агент не читает, не меняет и не удаляет: `.env` (кроме шаблонов `.env.example`),
  `id_rsa`/`id_ed25519`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `.npmrc`, `.netrc`, `.git-credentials`,
  `credentials.json`, `secrets.*`, а также `.git/config` и `.git/hooks` (там бывают токены и скрипты).
  Пользователь по-прежнему может открыть такие файлы сам в редакторе.
- Поиск по проекту пропускает секретные файлы, чтобы их содержимое не ушло в облачную модель.
- Папка проекта не может быть системным каталогом или корнем диска; «последний проект» из настроек
  тоже перепроверяется при запуске.
- Удаление — внутри проекта/домашней папки (в полном доступе — в любой папке), с защитой корня
  проекта, домашней папки, рабочего стола и системных каталогов.
- Импорт ZIP проверяет каждое имя из архива: `..`, абсолютные пути и буквы дисков отбрасываются,
  запись идёт только внутрь папки проекта; секретные файлы не перезаписываются. Свой распаковщик
  (без внешних программ) исключает «zip-slip» и подмену путей.
- Экспорт ZIP не включает секреты (`.env`, ключи, `.git/config`) и файлы больше 8 МБ, архив ограничен 25 МБ.

### Полный доступ к компьютеру
- Режим «Полный доступ» включён по умолчанию (`conf.fullAccess`), переключается в
  Настройки → Общие → Безопасность и виден бейджем в шапке. Он расширяет **только** список разрешённых
  папок для файловых инструментов и `run_command` (параметр `cwd`), а также поднимает лимит
  чтения файла с 2 до 10 МБ.
- Даже в полном доступе остаются запреты на файлы с секретами (`.env`, приватные ключи,
  `.git/config`, `credentials.json`, …). Это защищает от кражи ключей, если модель «уговорили»
  через текст файла или веб-страницу.
- Системные каталоги (`/etc`, `/usr`, `C:\Windows`, `Program Files`, `Library`, …) доступны
  для чтения и правки только после подтверждения, но **удалять** их нельзя даже в полном доступе:
  `delete_path` отказывает для корня диска и системных каталогов.
- `run_command` выполняется без песочницы ОС — это осознанное решение: пользователь выдаёт
  разрешение кнопкой. Команда не читает секреты через инструменты агента, но обычная оболочка
  технически может обратиться к файлу, если пользователь сам такую команду подтвердит.
- Инструмент `system` только читает сведения (ПК, диски, процессы, окна) без подтверждения.
  Действия, меняющие состояние (буфер обмена, громкость, блокировка, сон, снимок экрана),
  идут через подтверждение, как остальные опасные инструменты.
- `shutdown` и `restart` требуют **отдельного** флага `confirm: true` на уровне сервера:
  одна строка чата не выключит компьютер, даже если модель попросит.
- `kill` не завершает процессы с PID 1–4 и сам сервер LocalCode.

### Веб-интерфейс
- Отдаются только файлы из белого списка (`index.html`, `app.js`, `style.css`, `highlight.js`,
  `i18n.js`, `icon.ico`). Исходники сервера и любые другие файлы через HTTP не доступны.
- Заголовки: `Content-Security-Policy` (без inline-скриптов и сторонних источников), `X-Frame-Options: DENY`
  и `frame-ancestors 'none'` (нельзя встроить в чужой iframe), `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`, `Cross-Origin-*`, `Permissions-Policy`.
- Весь текст из модели и из файлов экранируется перед вставкой в HTML; подсветка кода тоже экранирует.
- Кнопка «без подтверждений» спрашивает подтверждение при включении: она снимает защиту от опасных
  действий агента.

### Сеть и внешние запросы
- `fetch_url` (чтение страниц) не ходит в локальную сеть: проверяются имя, IP-литералы (включая
  `2130706433`, `0x7f000001`, `::ffff:127.0.0.1`) и **все** ответы DNS; каждое перенаправление
  проверяется заново. Ответ ограничен по размеру.
- `web_search` ходит только на DuckDuckGo.
- Адрес сервера модели (`Base URL`) должен быть `http(s)`, без логина/пароля в адресе; облачные
  метаданные (`169.254.169.254`, `metadata.google.internal`, link-local) закрыты. Локальная Ollama
  и серверы в домашней сети при этом разрешены — это осознанная настройка пользователя.
- Загрузка моделей речи — только по https с проверкой адреса.

### Данные на диске
- `~/.localcode` создаётся с правами `0700`, `config.json` и служебный `session.json` — `0600` (на macOS/Linux).
  `session.json` нужен, чтобы повторный запуск открыл уже работающее окно (а не поднял второй сервер);
  файл удаляется при выходе.
  Запись конфига атомарная (временный файл + `rename`), чтобы он не «побился».
- `git` для статус-бара запускается с отключёнными `core.fsmonitor`, пейджером и хуками из чужого
  `.git/config` (иначе `git status` в подсунутом репозитории мог бы выполнить команду),
  с `GIT_CONFIG_NOSYSTEM=1` и без запросов пароля.
- Запуск программ/скриптов и «активного» содержимого (`.exe`, `.js`, `.html`, `.svg`, `.url`, …)
  через инструмент `open` запрещён — для этого есть терминал с явным подтверждением.

### Действия агента
- Опасные действия (`write_file`, `replace_in_file`, `apply_patch`, `run_command`, `open`,
  `delete_path`, `system`, Bluetooth) требуют подтверждения кнопкой «Выполнить»; для частых
  операций есть «Разрешить всегда» на время сеанса. Чтение сведений о ПК, список дисков,
  процессы и окна подтверждения не требуют.
- Сервер сам ограничивает пути и секреты, поэтому даже при «уговоре» модели через текст файла или
  веб-страницы (prompt injection) она не получит доступ к ключам и системным папкам.

## Что важно понимать

- **API-ключи** сейчас хранятся в браузере (`localStorage`) и передаются своему же локальному серверу
  при запросах. Они не шифруются: защита — это CSP, отсутствие сторонних скриптов и запрет чужих
  `Origin`. Не вставляйте в LocalCode сторонний JavaScript/CSS и не открывайте его на чужом компьютере.
- **Терминал и `run_command`** по замыслу выполняют произвольные команды от вашего имени. Подтверждение —
  главная защита; включайте «без подтверждений» только для доверенных задач.
- **Локальный процесс того же пользователя** (или вредоносная программа с вашими правами) может прочитать
  `~/.localcode` и подключиться к серверу. От такого уровня угроз защищает ОС, а не приложение.
- **HTTPS нет**: соединение идёт по loopback и не покидает компьютер. Не публикуйте порт наружу
  (не делайте проброс, не меняйте `HOST` на `0.0.0.0`).
- **Файлы настроек с ключами**: экспорт настроек может содержать API-ключи. При экспорте программа
  спрашивает, включать ли их; для передачи выбирайте вариант без ключей.
- Не подключайте в качестве `Base URL` чужие серверы, которым не доверяете: туда уйдут ваши сообщения
  и код, который вы отправите модели.

## Ограничение нагрузки (DoS)

- Частота запросов к `/api/*` ограничена: всплеск до 60 запросов, восстановление 8 в секунду; дальше
  сервер отвечает `429` с `Retry-After`. Это защищает от «шторма» локальных скриптов и случайных циклов.
- Обход каталогов (`search`, список файлов) ограничен 24 уровнями вложенности; символические ссылки
  не обходятся. Огромное дерево больше не может подвесить сервер.
- Терминал: не более 12 одновременных процессов, команда до 10 000 символов, вывод до 20 МБ на процесс;
  при медленном клиенте включается обратное давление, поэтому сервер не копит вывод в памяти.
  В интерфейсе хранится не больше 400 000 символов вывода.
- Тело запроса — только JSON, до 30 МБ (аудио — до 40 МБ), с таймаутами на чтение.

## Подлинность сборки и предупреждения об опасном коде

Ключей активации нет: программа бесплатная. `integrity.json` — подписанный список sha256
основных файлов, `integrity-pub.pem` — открытый ключ. Состояние видно в «Настройки → О программе»:
`official` (файлы совпадают), `modified` (файлы изменены), `tampered` (подпись подделана),
`unsigned` (сборка из исходников). `app/public/style.css` намеренно не входит в манифест.

При записи файлов и запуске команд сервер ищет типичные вирусные приёмы (скачать и выполнить,
скрытый PowerShell, автозапуск, майнер, кража паролей, reverse shell) и показывает предупреждение
с номером строки. Работа при этом не блокируется. Подробности и подпись релизов — в `INTEGRITY.md`.

## Если что-то пошло не так

1. Закройте окно LocalCode — сервер завершится, токен перестанет действовать.
2. Проверьте `localcode.log` (там больше нет токена в режиме окна).
3. При подозрении на утечку смените API-ключи у провайдера и удалите `~/.localcode/config.json`
   и ключи в настройках программы.
4. Запускайте `LocalCode.bat` — в консоли будет актуальная ссылка с токеном и сообщения об ошибках.

## English (short)

LocalCode binds to `127.0.0.1` only and requires a random per-run token (`x-token`, delivered to the
browser via `#token=…`). Host, Origin and Sec-Fetch-Site are checked; responses carry CSP and other
security headers; only whitelisted UI files are served. File access is confined to the project or home
folder, symlink escapes are rejected via `realpath`, and the agent cannot read or modify secret files
(`.env`, private keys, `.git/config`, …) or system folders. Outbound page fetching blocks loopback,
LAN and cloud-metadata addresses (DNS answers and every redirect are checked). `~/.localcode` is
`0700` and `config.json` is `0600`; git runs with hooks/fsmonitor/pager disabled. Destructive agent
actions require confirmation. API keys live in browser `localStorage` and are not encrypted; the
terminal can run arbitrary commands by design. Do not expose the port or open the app on an untrusted machine.

The app is free: there are no activation keys. `integrity.json` is a signed manifest of the main files
(styles are excluded on purpose); the build state is shown under Settings → About. Writes and terminal
commands are scanned for common malware patterns and produce a warning with the line number, without
blocking the work. See `INTEGRITY.md`.
